### The metric (this is the headline correction)

The naive "flip every dead cell" average is **not** a measure of elasticity: on a mostly empty torus almost every dead cell is nowhere near the matter, so turning it on just makes a cell that dies by itself while the matter never notices, and the "healed" test passes trivially. The naive number mostly measures **how empty the torus is**.

Both metrics are therefore reported, and **only the causal one is ranked**:

- `E_add_causal` / `E_remove_causal` (HEADLINE, used for the ranking): a flip is counted only if it actually **did something to the matter**, so a far-field flip that merely turns on a cell which dies alone in vacuum is dropped from both numerator and denominator. Concretely:
  - **additions** count only if the next generation differs from the background at some cell **other than** the one flipped, i.e. the flip actually reached the matter;
  - **removals** count for every live cell, since every live cell is already part of the matter.
- `E_add_all` / `E_remove_all`: the diluted artefact numbers over all dead / live cells, kept in the output and explicitly labelled as **not used for ranking**. On a nearly empty torus they mostly measure emptiness: for the isolated 2x2 block `E_add_all = 0.8889` while the honest causal value is `0.0000`.

A note on why the relevance filter is defined per direction: a removed cell in a solid block is refilled on the very next step, so the *global* configuration can already equal the background at generation 1. A literal "the next generation must differ" test therefore finds **zero** relevant removals for the exact matter this brief describes, which would make `E_remove_causal` a meaningless 0/0. That strict variant is still printed next to every entry as a labelled comparison column.

Both metrics use the same "healed" test: the state must become **exactly equal to some phase of that background's own cycle** within 120 generations. "Relaxed to something quiet" does not count. (A torus cycle already contains its own translates, so no separate translation search is needed or correct.)

### Crystal vs dust

A "solid you can hold" must also be **one big connected piece of matter**. A background made of many separated small objects has the same weak statistics as a lone block (almost all of the torus is vacuum between the objects), so each background is labelled with the size of its **largest 8-connected component** and its **component count**. Three grades are separated in the output: **dust** (no dominant component), **bulk** (one component holding >= 90% of the live cells) and **solid** (bulk AND background density >= 0.2). Bulk alone is not enough, because a trivial 5-cell blob also has one component covering 100% of its own live cells; the density floor is what excludes that case. A block lattice whose blocks sit 2 cells apart is uniform matter but has many components under strict 8-connectivity, so the 90% grade is used rather than demanding a single component.

## Limitations (honest)

- **Small torus.** Screening and scoring both run on a 16x16 torus (periodic boundaries, 256 cells). Healing events that would be transient or would spread beyond 256 cells on a large lattice may look like exact cycle recovery here. Small-torus artefacts are likely and were not excluded.
- **Capped rule sample.** survivors 91125 > cap 3000; sampled 3000 evenly with stride 30.375. Ranking is therefore over a sample, not over all survivors, whenever the cap bites.
- **Heal = exact return to a cycle phase.** A configuration counts as repaired only if it becomes *exactly* equal to some phase of the unperturbed cycle within 120 generations. A perturbation that heals by a different route (e.g. leaves a *different* valid background of the same rule) is scored as a failure, and a perturbation that heals only after re-entering through an unlikely path is missed.
- **Only one-cell flips.** Elasticity is measured for single-cell holes and single-cell bumps only; two-cell or larger damage is not modelled. A rule could resist large damage poorly and still score well here (or vice versa).
- **What "solid" required.** The solid table additionally demands bulk matter (one component >= 90% of live cells) and background density >= 0.2. Elasticity alone is not enough: a rule whose background is a few isolated still lifes can post a good causal score while being nothing like a macroscopic object, and the component/density columns are there to expose that.
- **Background choice.** For each rule the qualifying seed with the highest mean density is used as that rule's background (ties broken 2x2 block, then p=0.5, then p=0.15), and the phase used for the flips is that cycle's start. Numbers depend on that choice; other phases give different values even for the same rule. Life itself illustrates the hazard: its own attractors on this torus are too sparse to qualify, so its ranking entry is absent and its elasticity had to be measured off-screen.
- **All-dead false positive.** The all-dead state is a fixed point of every rule and every flipped-on cell then dies, which would trivially score `E_add = 1.0`. Those backgrounds (0 scored rules) were detected and excluded, and the stage-1 density filter excludes them from the start. The **causal filter removes the same trap in its weaker form**: a near-empty background can no longer earn a high `E_add` from far-field flips that never touch the matter, because those flips are not causally relevant and are dropped.
- **Runtime observed: 648.5 s**, with 262144 of 262144 rules examined in stage 1 (elapsed 437.3 s, budget 600 s) and 3000 scored in stage 2 (elapsed 211.1 s). Stage 1 finished inside its 600 s budget, so the full rule space is covered. Stage 2 is the part that overruns the brief's ~10 minute stage-1 budget when stage 1 and stage 2 are added together; the brief's budget applies to stage 1 and stage 1 met it.
